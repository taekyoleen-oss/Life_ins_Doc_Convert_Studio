# studio-harness — 갈래별 개발 오케스트레이터

**실행 모드: 서브 에이전트(워크플로)** — 갈래가 파일로 갈려 있어 결과만 돌려받으면 된다. 팀 통신은 쓰지 않는다.

## 에이전트

| 에이전트 | 갈래 | 정의 |
|---|---|---|
| `doc-sync-dev` | 산출방법서 ↔ 조건 반영 | `.claude/agents/doc-sync-dev.md` |
| `hwpx-dev` | 한글(HWPX) · 문서 형식 설정 | `.claude/agents/hwpx-dev.md` |
| `calc-flow-dev` | 모듈식 산출 흐름 화면 | `.claude/agents/calc-flow-dev.md` |
| `studio-qa` | 검토 · 통합 검증 | `.claude/agents/studio-qa.md` |

검증 명령은 `studio-verify` 스킬.

## 흐름

### 0. 컨텍스트 확인
- `_workspace/` 가 있고 일부만 고치라는 요청 → 그 갈래의 에이전트만 다시 부른다(이전 보고를 함께 넘긴다).
- 새 요청 → `_workspace/` 를 `_workspace_prev/` 로 옮기고 처음부터.

### 1. 정찰 (오케스트레이터가 직접)
요청을 갈래로 나누고, 갈래마다 **맡는 파일**과 **갈래 사이의 약속**(함수 이름·모양)을 정한다.
여럿이 고치는 파일(`components/Studio.tsx`)은 갈래마다 고칠 부분을 정해 준다.
`scripts/e2e.cjs` · `CLAUDE.md` 는 구현 에이전트가 건드리지 않는다 — 제안만 받는다.

### 2. 구현 → 검토 → 고침 (워크플로, 갈래마다 나란히)
```
pipeline(갈래들,
  갈래 => agent(구현 지시),                  // 그 갈래 에이전트 정의를 먼저 읽게 한다
  (보고, 갈래) => agent(검토 지시),           // studio-qa — 반박하려는 눈으로, 직접 돌려 본다
  (결함, 갈래) => 결함이 있으면 agent(고침 지시))
```
에이전트는 한 작업 폴더를 함께 쓴다 — `git stash/checkout/reset` 금지, 시험 출력 파일 이름에 갈래를 붙인다.

### 3. 통합 검증 (studio-qa 한 명, 차례로)
전체 tsc · vitest · eslint · build → e2e 에 제안 항목 더하고 실행 → `lib/methoddoc` 를 flexible_insurance 로 복사하고 그쪽 시험 → CLAUDE.md 에 규칙 문단 반영.

### 4. 마무리 (오케스트레이터)
결과를 직접 다시 확인하고(수치), 커밋·푸시, 한글 결과 블록. 실행 뒤 사용자에게 고칠 점을 묻는다.

## 데이터 전달
- 에이전트 → 오케스트레이터: 반환값(구조화 — 요약 · 파일 · 시험 · e2e 제안 · CLAUDE.md 문단 · 위험).
- 큰 산출물은 `_workspace/{단계}_{에이전트}_{이름}.md`.

## 에러 핸들링
- 에이전트가 실패하면 한 번 다시 부르고, 또 실패하면 그 갈래를 빼고 진행하며 보고에 빠진 것을 적는다.
- 통합 검증에서 고정값(보험료 · 환급률)이 바뀌면 멈추고 원인을 찾는다 — 기대값을 고쳐 맞추지 않는다.
- 사람이 확인해야 하는 것(실제 한글 프로그램에서 열리는지 등)은 "확인하지 못함"으로 보고한다.

## 테스트 시나리오
- 정상: "한글 내보내기에 머리말을 넣어줘" → 0 에서 부분 재실행으로 판단 → `hwpx-dev` 만 → `studio-qa` 검토 → 통합 검증.
- 오류: 구현 뒤 종신보험 월 250,000원이 달라짐 → 통합 검증이 멈춤 → 원인 갈래를 찾아 그 에이전트에게 되돌림.
