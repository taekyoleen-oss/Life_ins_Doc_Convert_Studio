# Life_ins_Doc_Convert_Studio 설계 · 연동 · LaTeX 변환 제안

## 1. 왜 따로 떼었나

산출방법서 ↔ 조건 변환은 flexible_insurance 안에서 시작했지만(`/method` 화면), 실무에서는 **여러 앱이 같은 변환을 필요로 한다**
(설계형 보험 앱, 일반 상품 설계기, 재보험 심사, 검증용 스크립트 …). 그래서 변환을 독립 앱으로 두고, 앱끼리는 중립 형식
**MethodSpec(JSON)** 한 가지로만 주고받는다.

```
            ┌────── Life_ins_Doc_Convert_Studio ───────┐
PDF·HWP·DOCX │ extract → parse ──► MethodSpec ◄── 조건(YAML) │
TEX·MD      │                      │                      │
            │     formulas + render ▼                      │
            │   산출방법서 (화면 · .tex · .md · .html)       │
            └──────────────────────┬───────────────────────┘
                                   │ MethodSpec .json
              flexible_insurance · 다른 앱 (adapter 하나씩)
```

## 2. 화면

위: 조건 | 산출방법서 (좌우), 아래: 위험률 표. 창 사이 막대로 크기를 바꾸고(두 번 누르면 처음 비율), 창마다 [⤢ 전체]·[– 숨기기], 머리의 [보기]에서 다시 켠다. 비율·숨김·펼친 카드는 브라우저에 기억한다.

### 카드 = 산출 단계 = 산출방법서 절 (2026-09-28)

카드를 기능별로 늘어놓으면(담보마다 카드 하나) 담보마다 유지자수부터 다시 정해야 해서, 사람이 "지금 무엇을 정하는지" 를 놓쳤다.
그래서 **산출 순서**로 다시 묶었다 — 사람 수를 먼저 정하고(집단), 그 사람 수로 보험금을, 보험금을 현가로, 현가를 보험료로.
산출방법서의 절 순서도 같아서 카드 ↔ 절이 1:1 이다.

| 카드 | 정하는 것 | 산출방법서 절 | 식 |
|---|---|---|---|
| M01 상품 기본정보 | 이름·종류·가입 조건 | 개요 | — |
| M03 이자율·저해지 | i · 표준이율 · w · ρ | 1.1 · 1.3 | — |
| M04 위험률 | 이름·유형·근거 (값 표는 아래 창) | 1.2 · 별첨 | — |
| **M05 보험료** | 집단마다 탈퇴 사유 · 납입면제 사유 → l·l′ 와 그 현가 | 1-라. 유지자수·납입자수 · 1-마. 계산기수 — 보험료 | `Q` · `l` · `l′` · `D` · `D′` · `N` · `N′` · `N*` |
| **B01 보장** | 담보 전부(더하기·복사·삭제) — 급부 위험률·금액·종료 나이·면책·집단 **+ 그 담보의 보험금의 현가**(l 은 M05 에서 가져온다) | 1-나. 보장 내용 · 1-바. 계산기수 — 보험금 | 담보마다 `d` · `S` · `C` · `M` · `PVB` |
| M06 사업비 | α_S · α_P · β_S · β_G · β′ · γ | 1-가. 예정기초율 | — |
| **M07 보험료의 계산** | (식만) | 1-사. 순보험료 및 영업보험료 | `P` · `P_base` · `G` |
| M08 준비금·환급금 | 해약공제 기간 · 문장 | 2 · 3 | `P_β` · `V` · 해약공제 · `W` |
| M09 따로 적는 식 | 표준 식 밖의 식 | 그 절 | — |

시산(성별·가입나이·납입기간·납입주기 → 10만원당·월 보험료)은 카드가 아니라 **카드 위의 [시산보험료 조건]** 줄에 따로 둔다 — 보험료 카드 안에 있으면 "조건"으로 오해하기 때문이다(계약 한 점은 조건에 저장하지 않는다). [보험료 계산] 표도 여기서 연다.

카드를 **보험료(M05) → 보장(B01)** 순서로 둔 것은 실무의 두 갈래를 산출 순서대로 옮긴 것이다 — 보험료는 "낼 사람"(납입자수 l′ → 납입기수 N\*),
보험금은 "받을 사람"(유지자수 l → 지급자수 d → 급부 현가 C). 두 쪽의 l 은 같은 집단에서 나오므로 **보험금 쪽은 l 을 다시 정하지 않고 M05 의 집단을 가져온다**
(어느 집단인지 적고 [M05 에서 보기]로 건너간다).

**담보는 B01 한 군데서만 고친다.** 처음에는 담보를 B01(급부·금액)과 M06(보험금의 현가) 두 곳에 나눠 두었는데, 담보를 더할 때 어느 카드에서 무엇을 적는지 헷갈렸다.
그래서 담보 하나를 **한 덩이**로 묶었다 — B01 의 담보 안에서 급부 위험률·금액·면책·집단과 그 담보의 C·M·PVB 를 함께 본다. 겹쳐 적던 칸도 하나로 줄였다(`지급 사유`는 담보 이름과 같은 말이라 없앴다 — 산출방법서에도 한 번만 나온다).
머리의 [수식 숨기기/보이기]로 카드의 식을 감출 수 있다.

**집단**(`groupModels`)은 조건에 새로 적는 항목이 아니다 — **탈퇴 위험률이 같은 담보를 묶은 것**이다. 그래서 MethodSpec 에 칸이 늘지 않았고,
M05 에서 집단의 탈퇴 사유를 고치면 그 집단의 담보가 함께 바뀌고, B01 에서 담보의 집단을 바꾸면 그 담보만 옮겨 간다.
같은 사유로 줄어드는 담보는 `l`·`l′` 가 똑같으니 식도 한 번만 싣는다(종신보험(암진단 포함)은 집단 둘 — 사망·80% 장해 / 사망·암).

### 식이 계산의 정의다 (`calc.ts`, 2026-09-27)

전에는 산출방법서의 식이 **보여 주기만** 했다 — 계산은 자유설계보험 엔진 코드에 박힌 식이 했고, 문서의 식을 고쳐도 값은 그대로였다.
조건을 바꾸는 것과 "그 조건으로 산출방법서의 식을 해석해 계산하는 것" 이 이어지지 않았다.

그래서 **산출방법서에 싣는 평문 수식 표기를 그대로 기계가 읽는 문법으로 정했다.** 새 문법을 만들지 않고, 이미 쓰던 표기가 문법이다.

```
l_x = l′_x = 100,000
Q_{x+t} = q_{x+t} + r_{x+t} − q_{x+t}·r_{x+t}/2
l_{x+t+1} = l_{x+t} × ( 1 − Q_{x+t} )
S_t = 1 × if( t = 0, 1 − 3/12, 1 )          ← 면책 90일
C_{x+t} = l_{x+t}·r_{x+t}·v^{t+½}
M_{x+t} = Σ_{u=t}^{n−1} S_u·C_{x+u}
PVB = M_x
N* = k · [ ( N′_x − N′_{x+m} ) − ( k−1 )/( 2·k )·( D′_x − D′_{x+m} ) ]
P = PVB / N*
```

| 정한 것 | 왜 |
|---|---|
| 아래첨자가 **자리**(`x` → t=0 · `x+t` → t · `x+t+1` → t+1 · `x+m` → m · `t` · `u` · 수) | 산출방법서가 이미 이렇게 적는다. `x+` 를 떼고 남은 것을 t·u·n·m 의 식으로 읽는다 |
| 이름의 아래첨자는 자리가 아닌 것(`α_S` · `P_base` · `P_β`) | 기호와 자리를 문법으로 가른다 — 따로 표를 두지 않아도 된다 |
| `Σ_{u≥t}` (끝은 n) · `Σ_{u=t}^{n−1}` · `if(조건, 참, 거짓)` · 비교 사슬 `40 ≤ x+t ≤ 59` · `min` · `max` · `round` | 실제 산출방법서에 필요한 만큼만. 연령 구간 배수·면책이 `if` 로, 누계가 `Σ` 로 적힌다 |
| 점화식은 왼쪽 자리로 안다(`l_{x+t+1} = …` → 앞자리에서) | 따로 표기를 만들지 않는다. 늦은 계산 + 기억(memo) 으로 풀고 스스로를 돌아 참조하면 알린다 |
| 읽을 수 없는 줄은 **문서에는 그대로, 계산에서만 뺀다** | 사람이 적은 설명 줄·특수한 식이 있어도 문서가 망가지지 않는다. 화면이 "계산 제외" 로 알린다 |
| `computeSpec(spec, 계약)` 은 담보 하나를 독립된 소형 상품으로 본다 | 자유설계보험 `computePlan` 과 같은 규칙(n = min(보험기간, 종료나이+1−가입나이), m = min(납입기간, n)) |

그래서 **조건을 고쳐도, 식을 고쳐도 계산이 바뀐다.** 카드(M05·K01·K02·K03)의 [식 고치기]와 Word·한글의 식 고치기가 같은 자리
(`formulas` 의 같은 `절|제목`)로 들어가고, K01·K02·K03 의 "시산" 이 그 식으로 바로 값을 보여 준다([되돌리기]로 자동 식으로).
다른 앱은 `lib/methoddoc` 만 가져다 `computeSpec` 을 부르면 된다 — 자유설계보험 엔진과 10만원당 보험료가 같은지 두 앱의 시험이 확인한다
(`tests/calc.test.ts` · flexible `tests/ui/default-product.test.ts`).

한계(2026-10-01 까지): 책임준비금·해지환급금은 식만 실었다 — 지금은 계산 표가 V·W·환급률 열까지 낸다(아래). 저해지형 `CSV` 만 0 으로 두고 그 값은 자유설계보험이 낸다.

### 보험료 계산 화면 — 엑셀처럼 (2026-09-27)

식이 맞는지 보려면 결국 **한 해 한 줄의 표**를 봐야 한다. 실무에서 엑셀로 하던 그 모양을 그대로 화면에 뒀다(`components/PremiumSheet.tsx`).
값은 `calc.ts` `calcSheets` 가 **산출방법서의 식을 읽어** 낸 것이라 따로 계산 코드가 없다 — 식을 고치면 표가 바뀐다.

| 자리 | 내용 |
|---|---|
| **왼쪽** | 계산에 앞서 정한 값 — 가입나이 x · 보장기간 n · 납입기간 m · 납입주기 k · 적용이율 i · 현가율 v · 보장금액 · 면책 · 사업비(`CalcSheet.inputs`). 내려받은 파일만으로 다시 세울 수 있게 파일에도 그대로 들어간다 |
| 표 왼쪽 두 열 | 경과기간 t · 연령 x+t (얼려 둔다) |
| 위험률 열 | 그 담보의 탈퇴 사유·납입면제 사유·급부 발생률 (표에서 온 값) |
| **현가율** | `v^t`(그 해 초 — D·D′ 가 쓴다) · `v^{t+½}`(그 해 가운데 — 급부는 연중앙에 생긴다고 보아 C 가 쓴다). 값이 아니라 적용이율에서 나오는 식이다 |
| 사람 수 | 탈퇴율 `Q` → 유지자수 `l` → 납입자수 `l′` → **지급자수 `d`** |
| 현가·누계 | `D` · `D′` (· 해지 `W`) → `N` · `N′` |
| 보험금 | 보장금액 배수 `S` (구간·면책) → 급부 현가 `C` → 누계 `M` |
| 준비금·환급금 | `V` · `V^{10만}` · 해약공제 · `W^{표준}` · `W` · 납입누계 · 환급률 (2·3 장의 식) |
| 오른쪽 | `N*` · `PVB` · `P` · 기준연납 · `G` · `G₁`(6자리) · `G_{10만}` · `P_β` · `α^{표준}` · `α^{공제}` → 10만원당 → 담보 보험료(× 가입금액 × 배수 ÷ 10만) |
| 열 제목·값을 누르면 | 그 값을 만든 **식**과 그 해에 **쓰인 값**(`CalcColumn.parts`) — 엑셀에서 칸을 눌러 수식을 보는 것과 같다 |

### 엑셀 수식으로 내려받기 (`calc-xlsx.ts` · `xlsx.ts`)

화면에서 보는 것으로는 부족하다 — 실무는 **엑셀에서 값을 바꿔 가며** 확인한다. 그래서 내려받는 `.xlsx` 를
**값이 아니라 수식**으로 만든다. 값으로 두는 것은 **계약·기초율과 위험률뿐**이고, 현가율부터 끝까지는 엑셀 수식이다.

```
l_{x+t+1} = l_{x+t} × ( 1 − Q_{x+t} )   →  =L2*(1-K2)
D_{x+t}   = l_{x+t}·v^t                 →  =(L3*I3)            ← I 열이 현가율 v^t
N_{x+t}   = Σ_{u≥t} D_{x+u}             →  =SUM(O3:O73)
M_{x+t}   = Σ_{u=t}^{n−1} S_u·C_{x+u}   →  =SUMPRODUCT(S3:S72,T3:T72)
P         = PVB / N*                    →  =($B$19/$B$18)
```

읽어 둔 식의 AST(`CalcColumn.eq`)를 A1 수식으로 옮긴다 — `Σ` 는 몸통이 자리(u)로만 도는 계열들의 곱이면
`SUM`·`SUMPRODUCT` 로, `if` 는 `IF` 로, 비교 사슬은 곱(`(40<=x)*(x<=59)`)으로, `v^t`·`v^{t+½}` 는 현가율 열로.
못 옮기는 식이 있으면 그 칸만 값으로 두어 파일이 망가지지 않게 한다.
기간·보장금액이 담보마다 다르므로 이름(`x_age`·`n_term`·`S_amt` …)은 **그 장에서만** 쓰는 이름으로 둔다(`localSheetId`).
담보마다 한 장, 첫 장이 합계다. 엑셀이 다시 계산한 값이 앱과 같은지 확인했다(차이 0 — Excel COM).

화면의 [이 담보만 CSV (값)] 는 값만 필요한 때를 위한 것이다. 지급자수 `d` 는 문서에 따로 싣지 않는다 — 급부 현가 `C = l·발생률·v^{t+½}` 의 `l·발생률` 부분이라 표에서만 열로 보여 준다(`BenefitModel.payout`).
담보 하나가 독립된 소형 상품이므로 담보마다 탭이 하나고, 합계는 담보 보험료의 합이다.

### 보장금액은 배수, 보험료는 1원당 → 6자리 → 10만원당, 준비금·환급금까지 식으로 (2026-10-01)

실무 산출방법서는 보장금액을 **가입금액의 배수**(사망 1배 · 암 진단 0.5배)로 적고, 보험료는 1원당으로 낸 뒤 맨 뒤에 가입금액을 곱한다. 이 앱도 그렇게 바꿨다.

| 정한 것 | 왜 |
|---|---|
| `BenefitSpec.multiple`(배수) · 가입금액은 시산 계약(`CalcContract.sumAssured`) | 조건은 산출방법서의 정보(배수)만 갖고, 얼마짜리 계약인지는 시산 줄에서 고른다. 옛 문서·다른 앱의 `amount`(원)도 그대로 읽는다 |
| 면책·삭감 = 기간(`waitDays` 30일~2년) + 그 기간 지급 비율(`waitPayRatio` — 면책 0 · 50% 삭감 0.5) → `S_t` | 암은 면책(0%), 특정 사망은 50% 삭감처럼 산출방법서가 다르게 적는다. 첫해 안이면 `if( t = 0, 1 − (1−ρ)·mo/12, 1 )`, 더 길면 해마다 겹치는 만큼 |
| 급부 위험률 칸을 없앰 — 탈퇴 사유(집단) 가운데 사망이 아닌 것(`eventRate`) | 진단형의 급부는 늘 그 담보를 소멸시키는 사유다. 두 곳에 같은 것을 적게 하지 않는다(일당형만 `rateId`) |
| `G₁ = round₆(G)` · `G_{10만} = round(G₁ × 100,000)` | 사용자의 규칙. 자유설계보험 엔진도 같은 반올림(`r6`)이라 두 앱이 정확히 같다(암 진단 162 → **163**, 월 342,000 → **342,500원**) |
| `Q = min(1, Σd − Σdᵢdⱼ/2)` | 최종 연령에서 사망률이 1 이면 합이 1 을 넘는다 — 엔진·엑셀 검산과 같게 1 로 막으니 연도별 준비금이 끝까지 같다 |
| M05 는 납입자수(l′ · D′ · N′ · N*), 유지자수(l · D · N)는 담보 안에서 | 보험료는 "낼 사람", 보험금은 "받을 사람" — 집단 식을 `group:`(유지자수)·`pay:`(납입자수) 둘로 갈라 카드가 제 것만 보인다 |
| 2·3 장의 식이 모두 계산되는 식 — `P_β` · `V` · `α^{공제} = min(α_S + α_P·round₅(P_base), α^{표준})` · 해약공제 · `W` · 납입누계 · 환급률 | 준비금·환급금도 문서의 식대로 계산 표·엑셀·파이썬에 열로 들어간다. `α^{표준}` 은 같은 식을 표준이율로 한 번 더 세운 값(`buildModel`), 저해지형 `CSV` 는 0 으로 둔다(그 값은 자유설계보험) |
| 식이 있는 카드마다 [수식 보이기](기본 숨김) · 카드를 열면 창 한가운데로 | 머리의 한 단추는 식이 없는 카드에도 걸려 있었다 |
| 계약 단위 탭 — 담보의 `unit` 이름에서(`unitNames`), [＋ 특약]은 그 이름의 첫 담보 | MethodSpec 에 칸을 늘리지 않는다(집단과 같은 방식). 보장·보험료 카드·계산 표·엑셀이 단위마다 따로 움직인다 |
| 엑셀은 계약 단위마다 한 장, 담보가 모두 한 장에, 맨 오른쪽에 결과 | 사용자의 검산 엑셀(`09_…_검산.xlsx`) 모양. 위험률·현가율은 공통 열이고 담보마다 구역, 담보마다 다른 값(n·m·배수)은 결과 칸을 가리킨다. 엑셀 재계산 = 앱 = 엔진(`scripts/check-calc-xlsx.ps1`) |
| Python 일괄 산출(`calc-py.ts` · `PythonPanel`) | 같은 AST 를 파이썬 셀로. 반올림은 `rnd()`(엑셀처럼 .5 올림 — 파이썬 `round()` 는 짝수로 간다), 0 으로 나누면 `div()`. Pyodide 로 브라우저에서 셀을 실행하고 `.py` 로 내려받는다. `tests/calc-py.test.ts` 가 이 PC 의 python 으로 돌려 앱과 같은 값인지 본다 |
| 시산 줄에 가입금액과 납입방법별(월·3개월·6개월·연납) 보험료 표 | 보험금의 현가는 같고 N* 만 다르다 — 한눈에 견준다. 식 읽기를 글자로 캐시해(`parseCached`) 한 번에 넷을 세워도 멈추지 않는다 |
| 표준 산출방법서 v5 | 담보 표 행(보험기간·배수·면책·삭감), 라. 두 덩이, 2·3 장 식. v4 문서의 옛 자동 식은 `V4_AUTO` 로 건너뛴다. 설명 속 첨자는 `{}` 로 묶는다(`α^{표준}`), 겹아래첨자(`V_{10만}_t`)는 KaTeX 가 거부해 `V^{10만}_t` 로 |

한계: `standards/*.hwpx` 는 한글 COM 이 멈춰 v5 로 다시 만들지 못했다(`scripts/make-standard-hwpx.ps1` — 한글을 한 번 직접 띄운 뒤 돌린다). 주계약과 다른 특약 조건(`units[].overrides`)은 카드에 없다(JSON 으로만).

### 가입 조건(정보) — 시산 기준(계약)은 계산하는 앱에

실제 산출방법서·사업방법서(DB손보·메리츠·흥국·교보 등 25건 조사)를 보면 문서에 실리는 것은 두 종류다.
이 앱은 **산출방법서의 전체 정보만** 다룬다 — 계약 한 점은 보험료를 계산할 때 필요한 입력이지 산출방법서의 정보가 아니므로
자유설계보험 상품 만들기의 **M02 계약정보**(기본값 40세 남 · 보험기간 자동 · 20년납 · 월납, 사용자가 바꿈)로 옮겼다(2026-09-22).

| 구분 | 조건 위치 | 내용 | 산출에 쓰나 |
|---|---|---|---|
| 가입 조건 (판매 범위) | M01 · `product` | 보험의 종류 · 보험종목(1종 무해지환급형 …) · 보험기간 × 납입기간 × 가입나이(남·여) 표 · 납입주기 · 가입금액 한도 · 갱신 | 아니오 — 산출방법서 개요에 싣는 정보. 원문 표기 그대로의 글자 |
| 시산 기준 (계약 한 점) | **이 앱에 없음** → 자유설계보험 M02 계약정보 · `contract` | "기준: 남자 40세, 100세만기 20년납, 월납, 1,000만원" | 예 — 계산하는 앱이 정한다. 이 앱은 읽지도 싣지도 않는다 |

되읽기: "가입 조건 \| 내용" 과 "(구분 \|) 보험기간 \| 보험료 납입기간 \| 가입나이" 표를 먼저 `product` 로 읽고 그 줄들을 본문 규칙에서 뺀다 —
"110세만기 · 20년납" 이 다른 본문 규칙에 섞이지 않게. 사업방법서 표의 병합 칸(빈 칸)은 위 행 값을 이어 쓴다.
`parse.ts` 는 가입나이·보험기간·납입기간(시산 기준)을 읽지 않고, `render.ts` 는 `contract` 가 채워져 있을 때만(자유설계보험이 낸 문서) "시산 기준" 표를 싣는다.
옛 조건 파일의 `contract:` 는 읽지 않고 알림만 준다. 자유설계보험은 `product` 를 쓰지 않는다(정보).

### 입력 칸 → 조건 파일 (`editYaml`)

값 한 칸이 바뀌면 그 스칼라의 글자 범위만 바꿔 끼우고 되읽어 확인한다 — 주석·줄 맞춤·순서가 그대로다.
항목을 더하고 지우는 것처럼 모양이 바뀔 때만 문서 트리로 고친다(주석은 남고 주석 앞 줄 맞춤만 한 칸으로 준다).
사업비 행·해지율 행·탈퇴 위험률 목록은 새로 만들 때 한 줄(흐름 표기)로 둔다 — `specToYaml` 과 같은 관례.

### 위험률 표 → 조건

표는 조건 파일에 싣지 않는다(길다). 표와 열 연결은 브라우저에 두고, 화면에 그릴 때 `attachTables` 가 이은 열을 `RateRef.table {ages, values, sex}` 로 붙인다 →
산출방법서 위험률 표의 "표" 칸("40~110세 71행 · 남·여")과 MethodSpec JSON 에 실린다. 한 위험률에 남·여 열을 이으면 **두 벌 다** `RateRef.tables {M, F}` 로 싣고(`table` 에는 옛 소비자용 한 벌 — 남), 자유설계보험이 계약정보 성별의 표를 고른다(`rateTable`).
열 이름으로 처음 잇기: "연령·나이" → 연령, 성별을 뺀 이름("사망률(남)" → "사망률")이 위험률 이름과 같거나 겹치면 그 위험률. [안 이은 열 → 새 위험률]은 이름마다 위험률 하나를 더한다(남·여 열은 한 위험률).
값 표가 붙은 위험률은 산출방법서 맨 뒤 "별첨 — 위험률 표"(연령 × 열, `rateGrid`)로 나간다 — Word·한글·PDF 에도 값이 실린다. 문서를 열거나 고쳐 올릴 때 그런 표(첫 열이 연령, 나머지가 수)가 있으면 `sheetFromDoc` 이 위험률 표 창으로 가져오고 열 이름으로 잇는다(고쳐 올리기는 내보낸 표와 다를 때만 바꾼다). parse 는 이 표를 조건 규칙에서 뺀다(`isRateValueTable`).

### 위험률 표 ↔ 조건 ↔ 산출방법서 ↔ 계산 앱 — 하나로

| 어디서 더하면 | 어디에 반영 |
|---|---|
| 표를 올림(`loadSheet`) | `autoMap` 이 이름으로 잇고, 조건에 없는 이름의 수 열은 `unlinkedGroups` → `addRates`(M04 에 새 위험률, 유형은 이름으로 어림) → `linkGroups` |
| M04 [＋ 위험률] / 지우기 (`onEdit`) | 표에 그 이름의 빈 열(`addEmptyColumn`) / 그 열 연결 해제(`unlinkRate`) |
| 산출방법서에 행을 더해 올림(`applyFile`·`applySource`) | `mergeSpec` 이 조건에 더하고 `syncSheetRates` 가 빈 열 · 별첨 표가 있으면 `sheetFromDoc` 이 표째 |
| 계산 앱(자유설계보험) | JSON 열기 `planFromSpec` 은 계약 성별의 표를 열로 · 검수 `applySpecToPlan` 은 고른 위험률 중 시트에 없는 이름을 열로(표 값 또는 0) |

값 표가 없는 위험률(`ratesWithoutTable`)은 상태줄 "표 없음 N"·M04 안내·JSON 내보내기 알림·위험률 표 창 [표 없는 위험률 → 빈 열]로 알린다 — 계산 앱에서 0 이 되기 때문이다. 시험: `tests/rates-flow.test.ts`, 자유설계보험 `tests/ui/rates-from-studio.test.ts`(Studio 의 `samples/08_위험률표_종합_남녀.csv` 를 읽음).

### 기본 상품 · 기본 위험률 모음 · 엑셀 검산

- 기본 상품 종신보험(암진단 포함): 사망·80% 장해(사망형) + 암 진단(진단형, 사망보험금의 50%, 90일 면책 → 첫해 급부 × (1 − 3/12), 100세). 납입면제 사유 = 80% 장해 · 암 진단(`basis.waiverRateIds`). 담보마다 그 담보의 탈퇴 사유인 사유는 납입면제 f 에서 뺀다 — 사망 담보는 f = 암, 암 진단 담보는 f = 장해(둘 다 납입자수는 사망·장해·암으로 준다). 자유설계보험 엔진도 같은 규칙(`PlanCoverage.waiverRate`)으로 고쳤다 — 전에는 암 진단 담보에서 암을 두 번 뺐다.
- 위험률 표: 공개 기본 위험률(`lib/base-rates.ts` — 자유설계보험의 공개 표, 0~110세 남·여)이 첫 화면·샘플의 표다. 사내 위험률 모음(엑셀 142계열, "외부 반출 금지")은 `scripts/import-rate-library.py` 가 이 PC 의 `private/` 에만 JSON 으로 두고, 앱은 [기본 위험률 모음] 창에서 골라 쓴다(공개 저장소라 커밋·배포하지 않는다).
- 엑셀 검산: 산출방법서 식을 엑셀 수식으로 적은 파일과 자유설계보험 계산값을 나란히 — 조건 JSON → 엔진 결과 JSON → 수식 엑셀 → 엑셀 재계산(COM)으로 차이 0 을 확인한다. 보험료(PVB·N*·P·P_base·G·10만원당 G·월보험료)와 연도별 준비금이 모두 같다.

### 패키지 (.lifepkg) — 조건 · 산출방법서 · 위험률 표 한 파일

압축하지 않은 ZIP(`zipStore`·`unzip` 재사용 — 새 의존성 없음). 사람이 읽는 파생물(산출방법서 Word·Markdown, MethodSpec JSON)도 넣어 이름을 .zip 으로 바꾸면 바로 꺼내 쓴다. 열 때는 `조건.yaml`(주석 보존)과 `위험률표.csv` + `package.json` 의 열 연결만 쓴다 — 조건.yaml 이 없고 JSON 만 있으면 거기서 조건을 만든다. 한 부분이 없어도(위험률 표 없음) 패키지다.
최근 작업은 파일이 아니라 브라우저(localStorage)에 조건·표 스냅샷으로 12개 — 저장·연 파일 이름으로 묶는다. 첫 화면과 샘플은 `sampleSheet` 가 공개 기본 위험률 표(`lib/base-rates.ts`)에서 그 조건의 위험률과 이름이 맞는 열만 떼어 한 세트로 보여 준다.

### 고친 산출방법서 → 조건 (`mergeSpec`)

표준 양식이면 문서가 곧 조건이다: 담보 표에서 지운 칸(면책 `없음`, 구간 `※` 줄 삭제)과 위험률 표에서 지운 행(담보가 쓰지 않는 것)도 조건에서 뺀다. 담보 표에만 적은 위험률 이름은 계열로 더하고 경고한다.
문서의 식이 **고치기 전 조건**의 자동 식과 같으면(위험률·담보를 바꿔 새 자동 식과 달라졌을 뿐) 사람이 고친 식이 아니므로 조건에 남기지 않는다 — 옛 식이 새 자동 식을 덮는 일이 없게.

### 대응 위치 (mdTeX Studio 의 "선택 영역 미러링"을 조건 단위로)

mdTeX Studio 는 **소스 줄 번호**를 앵커로 쓴다. 여기서는 한 조건이 문서 여러 곳에 흩어지므로 **조건 경로**를 앵커로 쓴다.

| 방향 | 방법 |
|---|---|
| 조건 줄 → 산출방법서 | YAML 을 파싱할 때 경로마다 줄 범위를 적어 둔다(`yamlToSpec().ranges`). 고른 줄의 가장 깊은 경로 → 같거나 아래 경로를 가진 블록, 없으면 가장 가까운 윗 경로의 블록 |
| 산출방법서 → 조건 줄 | 블록의 `data-path`("a\|b") → 그 경로의 줄 범위(없으면 윗 경로) |
| 조건 ↔ 원문 | 불러올 때 남긴 근거(Evidence: 경로·"본문 55줄"·"표 14") |

예: `amount: 100000000` 줄 → 담보 표의 그 행 + 그 담보의 보험금 현가 식. `r80` 위험률 → 위험률 표의 행 + 그것을 탈퇴 사유로 쓰는 집단의 유지자수 식.
식 블록에는 조건 경로 말고 식의 짝(`formula:pv.N` 꼴)도 달려 있어, 식만 맡은 카드(K01·K02·K03·M05)가 자기 식 덩이만 정확히 짚는다(조건 파일의 줄이 아니므로 줄 짝짓기는 지나간다).

## 4. 제안 — 산출방법서를 불러와 LaTeX 로 고치기

지금 되는 것: `.tex` 는 그대로 LaTeX 탭에 올라가 고칠 수 있고, PDF·HWP·DOCX 는 조건으로 옮긴 뒤 **조건에서 만든 LaTeX** 를 고친다.
원문 모양 그대로 LaTeX 로 옮기려면 아래 단계가 필요하다.

| 단계 | 내용 | 난이도 |
|---|---|---|
| ① 원문 보존 LaTeX | 추출한 문단·표(ExtractedDoc)를 그대로 `\section`·`tabular` 로 옮긴 골격. 번호 체계(1. 가. (1))로 절을 나눈다 | 낮음 — `latexToDoc` 의 반대 방향 |
| ② HWP 수식 → LaTeX | HWP 5.x 수식 객체는 한컴 수식 스크립트(`x sup 2 over y`)로 저장돼 있다. 지금은 `[수식]` 자리표시자로 두는데, 스크립트를 꺼내 규칙으로 `\frac{x^2}{y}` 로 바꿀 수 있다 | 중간 — 문법이 작고 규칙적이다 |
| ③ PDF 수식 이미지 → LaTeX | PDF 에는 수식이 그림으로만 있는 경우가 많다. mdTeX Studio 의 "이미지 → 수식"(Claude Vision, 사용자 API 키)을 가져와, pdf.js 로 그 쪽을 그린 뒤 영역을 골라 LaTeX 로 옮긴다 | 중간 — 기능이 이미 다른 앱에 있다 |
| ④ 수식 대응 | 옮긴 원문 수식과 조건에서 만든 식을 나란히 두고 차이를 표시(예: 원문은 `1 − q − r`, 조건은 `+ q·r/2`) | 높음 — 기호 정규화가 필요 |

권장 순서: ① → ② → ③. ①②는 규칙만으로 되고, ③은 API 키가 있을 때만 켜는 선택 기능으로 둔다.
스캔 PDF · 그림 파일 전체를 조건으로 옮기는 기능(③을 넓힌 것 — 구현됨)은 [`이미지-PDF-변환-설계.md`](이미지-PDF-변환-설계.md), 올려 볼 샘플과 시험 순서는 [`../samples/README.md`](../samples/README.md).
편집의 중심은 LaTeX 가 아니라 **Word·한글의 표준 산출방법서**로 정했다(아래 §4-1).

## 4-1. 표준 산출방법서 — Word·한글로 고치기

실무에서 익숙한 Word·한글을 편집의 중심으로 두고, 앱이 **정확히 되읽는 양식**을 정했다(`STANDARD_FORMAT = "표준 산출방법서 v4"`).
앱이 내는 산출방법서가 곧 그 양식이다 — 화면·Markdown·LaTeX·Word 모두 같은 블록에서 나온다.

| 결정 | 까닭 |
|---|---|
| 양식 표시 = 개요 표의 `양식 \| 표준 산출방법서 v4` 행 | 표는 DOCX·HWPX 어디서나 온전히 읽힌다. 이 행이 있을 때만 식·주석·절까지 읽고, 없으면 지금처럼 값만 |
| 식은 문단 — `[식] 제목` + 식 줄 + `※ 설명` | DOCX·HWPX 추출은 문단 순서를 지키지만 표와 문단 사이 순서는 잃는다. 순서가 필요한 것(식·주석·절)은 문단에, 칸이 필요한 것(값)은 표에 |
| 조건·MD·LaTeX 의 식 표기는 평문(`l_{x+t+1}`), Word 는 Word 수식 | 평문은 되읽기가 정확하다. Word 는 식 줄을 독립 수식(`m:oMathPara`)으로 써서 조판된 식으로 보인다 — 한글은 독립 수식만 가져오므로(글 속 수식은 버림) 글·표 속 기호는 글자 첨자로. Word 수식(OMML)·한글 수식 스크립트·서식 첨자는 평문 표기로 바꿔 읽는다 |
| (v2) 식마다 설명을 위에, 식을 아래에 · 한 줄에 식 하나 · 식 줄간격 1.5 · 본문 12pt · 소제목 14pt | 실무 산출방법서의 모양. 긴 식은 가운데쯤의 + · − 앞에서 나눈다(`wrapEquation` — 한글은 긴 식을 쪽 밖으로 넘긴다) |
| (v2) `기호의 정의` 절 · 납입주기 k · 발생률 r · 저해지 비율 ρ | 기간·주기 기호를 먼저 정의한다. k 를 납입주기로 쓰므로 발생률은 r, 위험률 id 도 `r80` 처럼. 절은 조건에서 만들고 읽지 않는다 |
| (v2) 담보마다 세로 표, 현가율 값 행 없음 | 9칸 넓은 표는 쪽을 넘쳤다. v^t 는 이율에서 계산하는 값이라 문서에 싣지 않는다 |
| (v3) 식 절을 산출 순서로 — 탈퇴자·유지자·납입자 / 보험료의 현가 / 보험금의 현가 / 보험료의 계산 | 조건 카드와 1:1 로 맞춘다. 유지자수·납입자수는 담보가 아니라 **집단**마다 한 번, 담보 표에 `집단` 행이 늘었다 |
| (v3) 표기가 곧 계산 문법 | 문서의 식을 `calc.ts` 가 읽어 계산한다 — 식을 고치면 보험료가 바뀐다(위 "식이 계산의 정의다") |
| (v4) **큰 장 셋 + 별첨**, 장 안을 `가.`·`나.` 소제목으로 | 실무 산출방법서(`samples/02_실무양식_든든건강보험_산출방법서.md`)를 다시 살펴보니 `1. 보험료의 계산에 관한 사항` 안에 기초율·보장·기호·계산기수가 모두 들어가고, `2. 책임준비금` · `3. 해지환급금` 이 따로 장이었다. v3 는 이 모두를 같은 깊이의 절 여덟 개로 늘어놓아 "보험료가 위쪽에만 있는" 모양이 되었다 |
| (v4) `다. 기호의 정의` 의 l·l′ 은 **집단마다 한 줄** | 담보가 곱하는 l 이 집단마다 다르다(암 진단과 암 입원·수술은 탈퇴 사유가 달라 집단이 갈린다). 한 줄로 뭉치면 어느 l 인지 알 수 없다. 조건에 적는 항목이 아니라 **늘 다시 만드는** 절이라, 담보·집단·납입면제를 고치면 저절로 따라온다 |
| (v4) 납입면제 사유는 `가.` 에 `f_x : A · B` 로, 집단 식은 남은 사유만 | f 는 한 값이 아니다 — 담보의 탈퇴 사유이기도 한 사유는 두 번 빼지 않으려고 그 집단의 f 에서 뺀다. 그래서 `가.` 는 사유 전부와 결합(`Σ − Σ_{i<j} 곱/2`)을, 집단 식은 저마다 남은 사유를 적는다 |
| (v4) 2·3 장은 `※ 사항` 을 식보다 앞에 | 뒤에 두면 되읽을 때 마지막 식의 덧붙임(`※`)으로 빨려 들어갔다 |
| (v4) 위험률 출처는 **가상 이름만** | 저장소가 공개다. `경험생명표(가상) 사망률` 처럼 적어 실제 출처(회사·호수·표 이름)를 알 수 없게 한다. 사용자 문서를 **읽는** 쪽은 실제 출처 글귀를 그대로 읽는다 |
| 자동 식과 같은 식은 조건에 싣지 않는다 | 조건이 바뀌면 식도 따라 바뀌어야 한다. 사람이 고친 식은 `formulas` 의 같은 `절|제목`으로 들어가 자동 식을 대신하고(그 단계 카드에서 고치거나 되돌린다), 아주 새 식만 M09 에 남는다 |
| 위험률 표에 **기호** 칸 | 담보가 가리키는 위험률 id 가 문서를 거쳐도 그대로 돌아온다 |
| 작성일은 조건에 적힌 것만 싣는다 | 오늘 날짜가 찍히면 되읽을 때 조건이 아닌 값이 섞인다(자유설계보험 인쇄는 `today` 를 넘겨 날짜를 찍는다) |
| 상품별 견본은 목록 한 줄 | `lib/standards.ts` 의 `STANDARDS` — 파일 이름 `표준_산출방법서_<이름>`. `.hwpx` 는 한글에서 `.docx` 를 저장한 것 |

흐름: [Word 내려받기] → Word·한글에서 고침 → [고친 Word·한글 올리기] = `parseMethodDoc` → `mergeSpec`(식·주석·절·회사/판/비고까지) → `patchYaml`(조건 파일 주석 유지).
쓰는 규칙은 [`../standards/README.md`](../standards/README.md).

## 7. 제안 — AI 보조

flexible_insurance 의 `llm.ts`(규칙이 못 찾은 항목만 문단 발췌로 묻기)가 이 모듈에 그대로 들어 있다.
mdTeX Studio 처럼 **사용자가 앱에서 API 키를 입력**하는 방식으로 켜면 서버 없이 쓸 수 있다.
특히 **담보 표**가 규칙으로 잘 안 뽑히는 외부 PDF(지금은 담보 0개)에서 효과가 크다.

## 8. 알려진 한계

- 외부 PDF 의 **담보**는 규칙으로 뽑지 못한다(이 앱이 낸 문서의 담보 표만 되읽는다) — 직접 적거나 AI 보조.
- 표준 산출방법서의 **계약 단위 표**(주계약·특약)는 이름·담보만 보여 주는 표라 [열기]로 되살리지 않는다 — [조건에 반영]은 지금 계약 단위를 그대로 둔다.
- **납입기간**은 산출방법서에 없는 경우가 대부분이다(사업방법서 소관).
- 위험률 **값 표**는 조건 파일에 싣지 않는다 — 아래 위험률 표 창에서 열을 이어 붙이고, JSON 과 산출방법서 별첨에는 실린다.
- 위험률 표는 XLSX 첫 시트만 읽는다(옛 .xls 는 못 읽음 — .xlsx·.csv 로 저장). 수식 칸은 Excel 이 저장해 둔 값을 쓴다.
- 문장 수정은 조건이 아니라서 [조건에 반영] 되지 않는다 — LaTeX·Markdown 파일로 내려받아 보관한다.
- 일부 PDF 는 기호 글꼴이 깨진 글자로 추출된다(pdf.js 글자 레이어 한계).
