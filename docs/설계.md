# Life_ins_Doc_Convert_Studio 설계 · 연동 · LaTeX 변환 제안

## 1. 왜 따로 떼었나

산출방법서 ↔ 조건 변환은 flexible_insurance 안에서 시작했지만(`/method` 화면), 실무에서는 **여러 앱이 같은 변환을 필요로 한다**
(설계형 보험 앱, 일반 상품 설계기, 재보험 심사, 검증용 스크립트 …). 그래서 변환을 독립 앱으로 두고, 앱끼리는 중립 형식
**MethodSpec(JSON)** 한 가지로만 주고받는다.

```
            ┌────── Life_ins_Doc_Convert_Studio ───────┐
PDF·HWP·DOCX │ extract → parse ──► MethodSpec ◄── 조건(YAML) │
TEX·MD      │                      │                      │
            │     formulas + render ▼                      │
            │   산출방법서 (화면 · .tex · .md · .html)       │
            └──────────────────────┬───────────────────────┘
                                   │ MethodSpec .json
              flexible_insurance · 다른 앱 (adapter 하나씩)
```

## 2. 화면

위: 조건 | 산출방법서 (좌우), 아래: 위험률 표. 창 사이 막대로 크기를 바꾸고(두 번 누르면 처음 비율), 창마다 [⤢ 전체]·[– 숨기기], 머리의 [보기]에서 다시 켠다. 비율·숨김·펼친 카드는 브라우저에 기억한다.

| 영역 | 내용 |
|---|---|
| 왼쪽 · 입력 | 단계 카드(M01~M08, 담보는 C01…) — 자유설계보험 빌더와 같은 모양·코드. 칸 값은 조건 파일에서 읽고, 고치면 `editYaml` 로 그 칸만 파일에 쓴다(따로 상태 없음). 칸 경로 = 산출방법서 블록 경로 |
| 왼쪽 · YAML | 조건 파일(YAML). CodeMirror. 문법 오류 줄은 붉게, 오른쪽에서 고른 조건은 앰버색 |
| 오른쪽 · 산출방법서 | 조건으로 만든 문서. 수식은 KaTeX. 표의 행·수식마다 조건 경로가 달려 있다. [＋ 수식 더하기] 견본 → 조건 식(M08) |
| 오른쪽 · LaTeX / Markdown | 산출방법서 원문. 고치면 ● 표시 → [조건에 반영]. [수식·기호 견본] → 커서 자리에 식·기호·절·표 |
| 오른쪽 · 원문 | 불러온 문서의 본문 N줄·표 N, 줄마다 읽어 낸 조건 딱지. PDF 는 원본 보기 |
| 아래 · 위험률 표 | 붙여넣기·CSV·TSV·XLSX. 첫 행 = 열 이름. 열마다 [잇기]: 연령 / 위험률(rates[].id) + 성별 / 쓰지 않음 / 새 위험률로 더하기 |

### 가입 조건(정보) — 시산 기준(계약)은 계산하는 앱에

실제 산출방법서·사업방법서(DB손보·메리츠·흥국·교보 등 25건 조사)를 보면 문서에 실리는 것은 두 종류다.
이 앱은 **산출방법서의 전체 정보만** 다룬다 — 계약 한 점은 보험료를 계산할 때 필요한 입력이지 산출방법서의 정보가 아니므로
자유설계보험 상품 만들기의 **M02 계약정보**(기본값 40세 남 · 보험기간 자동 · 20년납 · 월납, 사용자가 바꿈)로 옮겼다(2026-09-22).

| 구분 | 조건 위치 | 내용 | 산출에 쓰나 |
|---|---|---|---|
| 가입 조건 (판매 범위) | M01 · `product` | 보험의 종류 · 보험종목(1종 무해지환급형 …) · 보험기간 × 납입기간 × 가입나이(남·여) 표 · 납입주기 · 가입금액 한도 · 갱신 | 아니오 — 산출방법서 개요에 싣는 정보. 원문 표기 그대로의 글자 |
| 시산 기준 (계약 한 점) | **이 앱에 없음** → 자유설계보험 M02 계약정보 · `contract` | "기준: 남자 40세, 100세만기 20년납, 월납, 1,000만원" | 예 — 계산하는 앱이 정한다. 이 앱은 읽지도 싣지도 않는다 |

되읽기: "가입 조건 \| 내용" 과 "(구분 \|) 보험기간 \| 보험료 납입기간 \| 가입나이" 표를 먼저 `product` 로 읽고 그 줄들을 본문 규칙에서 뺀다 —
"110세만기 · 20년납" 이 다른 본문 규칙에 섞이지 않게. 사업방법서 표의 병합 칸(빈 칸)은 위 행 값을 이어 쓴다.
`parse.ts` 는 가입나이·보험기간·납입기간(시산 기준)을 읽지 않고, `render.ts` 는 `contract` 가 채워져 있을 때만(자유설계보험이 낸 문서) "시산 기준" 표를 싣는다.
옛 조건 파일의 `contract:` 는 읽지 않고 알림만 준다. 자유설계보험은 `product` 를 쓰지 않는다(정보).

### 입력 칸 → 조건 파일 (`editYaml`)

값 한 칸이 바뀌면 그 스칼라의 글자 범위만 바꿔 끼우고 되읽어 확인한다 — 주석·줄 맞춤·순서가 그대로다.
항목을 더하고 지우는 것처럼 모양이 바뀔 때만 문서 트리로 고친다(주석은 남고 주석 앞 줄 맞춤만 한 칸으로 준다).
사업비 행·해지율 행·탈퇴 위험률 목록은 새로 만들 때 한 줄(흐름 표기)로 둔다 — `specToYaml` 과 같은 관례.

### 위험률 표 → 조건

표는 조건 파일에 싣지 않는다(길다). 표와 열 연결은 브라우저에 두고, 화면에 그릴 때 `attachTables` 가 이은 열을 `RateRef.table {ages, values, sex}` 로 붙인다 →
산출방법서 위험률 표의 "표" 칸("40~110세 71행 · 남·여")과 MethodSpec JSON 에 실린다. 한 위험률에 남·여 열을 이으면 **두 벌 다** `RateRef.tables {M, F}` 로 싣고(`table` 에는 옛 소비자용 한 벌 — 남), 자유설계보험이 계약정보 성별의 표를 고른다(`rateTable`).
열 이름으로 처음 잇기: "연령·나이" → 연령, 성별을 뺀 이름("사망률(남)" → "사망률")이 위험률 이름과 같거나 겹치면 그 위험률. [안 이은 열 → 새 위험률]은 이름마다 위험률 하나를 더한다(남·여 열은 한 위험률).
값 표가 붙은 위험률은 산출방법서 맨 뒤 "별첨 — 위험률 표"(연령 × 열, `rateGrid`)로 나간다 — Word·한글·PDF 에도 값이 실린다. 문서를 열거나 고쳐 올릴 때 그런 표(첫 열이 연령, 나머지가 수)가 있으면 `sheetFromDoc` 이 위험률 표 창으로 가져오고 열 이름으로 잇는다(고쳐 올리기는 내보낸 표와 다를 때만 바꾼다). parse 는 이 표를 조건 규칙에서 뺀다(`isRateValueTable`).

### 위험률 표 ↔ 조건 ↔ 산출방법서 ↔ 계산 앱 — 하나로

| 어디서 더하면 | 어디에 반영 |
|---|---|
| 표를 올림(`loadSheet`) | `autoMap` 이 이름으로 잇고, 조건에 없는 이름의 수 열은 `unlinkedGroups` → `addRates`(M04 에 새 위험률, 유형은 이름으로 어림) → `linkGroups` |
| M04 [＋ 위험률] / 지우기 (`onEdit`) | 표에 그 이름의 빈 열(`addEmptyColumn`) / 그 열 연결 해제(`unlinkRate`) |
| 산출방법서에 행을 더해 올림(`applyFile`·`applySource`) | `mergeSpec` 이 조건에 더하고 `syncSheetRates` 가 빈 열 · 별첨 표가 있으면 `sheetFromDoc` 이 표째 |
| 계산 앱(자유설계보험) | JSON 열기 `planFromSpec` 은 계약 성별의 표를 열로 · 검수 `applySpecToPlan` 은 고른 위험률 중 시트에 없는 이름을 열로(표 값 또는 0) |

값 표가 없는 위험률(`ratesWithoutTable`)은 상태줄 "표 없음 N"·M04 안내·JSON 내보내기 알림·위험률 표 창 [표 없는 위험률 → 빈 열]로 알린다 — 계산 앱에서 0 이 되기 때문이다. 시험: `tests/rates-flow.test.ts`, 자유설계보험 `tests/ui/rates-from-studio.test.ts`(Studio 의 `samples/08_위험률표_종합_남녀.csv` 를 읽음).

### 패키지 (.lidpkg) — 조건 · 산출방법서 · 위험률 표 한 파일

압축하지 않은 ZIP(`zipStore`·`unzip` 재사용 — 새 의존성 없음). 사람이 읽는 파생물(산출방법서 Word·Markdown, MethodSpec JSON)도 넣어 이름을 .zip 으로 바꾸면 바로 꺼내 쓴다. 열 때는 `조건.yaml`(주석 보존)과 `위험률표.csv` + `package.json` 의 열 연결만 쓴다 — 조건.yaml 이 없고 JSON 만 있으면 거기서 조건을 만든다. 한 부분이 없어도(위험률 표 없음) 패키지다.
최근 작업은 파일이 아니라 브라우저(localStorage)에 조건·표 스냅샷으로 12개 — 저장·연 파일 이름으로 묶는다. 첫 화면과 샘플은 `sampleSheet` 가 견본 표(`lib/rate-sample.ts` = `samples/08…csv`)에서 그 조건의 위험률과 이름이 맞는 열만 떼어 한 세트로 보여 준다.

### 고친 산출방법서 → 조건 (`mergeSpec`)

표준 양식이면 문서가 곧 조건이다: 담보 표에서 지운 칸(면책 `없음`, 구간 `※` 줄 삭제)과 위험률 표에서 지운 행(담보가 쓰지 않는 것)도 조건에서 뺀다. 담보 표에만 적은 위험률 이름은 계열로 더하고 경고한다.
문서의 식이 **고치기 전 조건**의 자동 식과 같으면(위험률·담보를 바꿔 새 자동 식과 달라졌을 뿐) 사람이 고친 식이 아니므로 조건에 남기지 않는다 — 옛 식이 새 자동 식을 덮는 일이 없게.

### 대응 위치 (mdTeX Studio 의 "선택 영역 미러링"을 조건 단위로)

mdTeX Studio 는 **소스 줄 번호**를 앵커로 쓴다. 여기서는 한 조건이 문서 여러 곳에 흩어지므로 **조건 경로**를 앵커로 쓴다.

| 방향 | 방법 |
|---|---|
| 조건 줄 → 산출방법서 | YAML 을 파싱할 때 경로마다 줄 범위를 적어 둔다(`yamlToSpec().ranges`). 고른 줄의 가장 깊은 경로 → 같거나 아래 경로를 가진 블록, 없으면 가장 가까운 윗 경로의 블록 |
| 산출방법서 → 조건 줄 | 블록의 `data-path`("a\|b") → 그 경로의 줄 범위(없으면 윗 경로) |
| 조건 ↔ 원문 | 불러올 때 남긴 근거(Evidence: 경로·"본문 55줄"·"표 14") |

예: `amount: 100000000` 줄 → 담보 표의 그 행 + 그 담보의 유지자수·납입자수 식. `r80` 위험률 → 위험률 표의 행 + 그것을 탈퇴 사유로 쓰는 담보식.

## 4. 제안 — 산출방법서를 불러와 LaTeX 로 고치기

지금 되는 것: `.tex` 는 그대로 LaTeX 탭에 올라가 고칠 수 있고, PDF·HWP·DOCX 는 조건으로 옮긴 뒤 **조건에서 만든 LaTeX** 를 고친다.
원문 모양 그대로 LaTeX 로 옮기려면 아래 단계가 필요하다.

| 단계 | 내용 | 난이도 |
|---|---|---|
| ① 원문 보존 LaTeX | 추출한 문단·표(ExtractedDoc)를 그대로 `\section`·`tabular` 로 옮긴 골격. 번호 체계(1. 가. (1))로 절을 나눈다 | 낮음 — `latexToDoc` 의 반대 방향 |
| ② HWP 수식 → LaTeX | HWP 5.x 수식 객체는 한컴 수식 스크립트(`x sup 2 over y`)로 저장돼 있다. 지금은 `[수식]` 자리표시자로 두는데, 스크립트를 꺼내 규칙으로 `\frac{x^2}{y}` 로 바꿀 수 있다 | 중간 — 문법이 작고 규칙적이다 |
| ③ PDF 수식 이미지 → LaTeX | PDF 에는 수식이 그림으로만 있는 경우가 많다. mdTeX Studio 의 "이미지 → 수식"(Claude Vision, 사용자 API 키)을 가져와, pdf.js 로 그 쪽을 그린 뒤 영역을 골라 LaTeX 로 옮긴다 | 중간 — 기능이 이미 다른 앱에 있다 |
| ④ 수식 대응 | 옮긴 원문 수식과 조건에서 만든 식을 나란히 두고 차이를 표시(예: 원문은 `1 − q − r`, 조건은 `+ q·r/2`) | 높음 — 기호 정규화가 필요 |

권장 순서: ① → ② → ③. ①②는 규칙만으로 되고, ③은 API 키가 있을 때만 켜는 선택 기능으로 둔다.
스캔 PDF · 그림 파일 전체를 조건으로 옮기는 기능(③을 넓힌 것 — 구현됨)은 [`이미지-PDF-변환-설계.md`](이미지-PDF-변환-설계.md), 올려 볼 샘플과 시험 순서는 [`../samples/README.md`](../samples/README.md).
편집의 중심은 LaTeX 가 아니라 **Word·한글의 표준 산출방법서**로 정했다(아래 §4-1).

## 4-1. 표준 산출방법서 — Word·한글로 고치기

실무에서 익숙한 Word·한글을 편집의 중심으로 두고, 앱이 **정확히 되읽는 양식**을 정했다(`STANDARD_FORMAT = "표준 산출방법서 v2"`).
앱이 내는 산출방법서가 곧 그 양식이다 — 화면·Markdown·LaTeX·Word 모두 같은 블록에서 나온다.

| 결정 | 까닭 |
|---|---|
| 양식 표시 = 개요 표의 `양식 \| 표준 산출방법서 v2` 행 | 표는 DOCX·HWPX 어디서나 온전히 읽힌다. 이 행이 있을 때만 식·주석·절까지 읽고, 없으면 지금처럼 값만 |
| 식은 문단 — `[식] 제목` + 식 줄 + `※ 설명` | DOCX·HWPX 추출은 문단 순서를 지키지만 표와 문단 사이 순서는 잃는다. 순서가 필요한 것(식·주석·절)은 문단에, 칸이 필요한 것(값)은 표에 |
| 조건·MD·LaTeX 의 식 표기는 평문(`l_{x+t+1}`), Word 는 Word 수식 | 평문은 되읽기가 정확하다. Word 는 식 줄을 독립 수식(`m:oMathPara`)으로 써서 조판된 식으로 보인다 — 한글은 독립 수식만 가져오므로(글 속 수식은 버림) 글·표 속 기호는 글자 첨자로. Word 수식(OMML)·한글 수식 스크립트·서식 첨자는 평문 표기로 바꿔 읽는다 |
| (v2) 식마다 설명을 위에, 식을 아래에 · 한 줄에 식 하나 · 식 줄간격 1.5 · 본문 12pt · 소제목 14pt | 실무 산출방법서의 모양. 긴 식은 가운데쯤의 + · − 앞에서 나눈다(`wrapEquation` — 한글은 긴 식을 쪽 밖으로 넘긴다) |
| (v2) `기호의 정의` 절 · 납입주기 k · 발생률 r · 저해지 비율 ρ | 기간·주기 기호를 먼저 정의한다. k 를 납입주기로 쓰므로 발생률은 r, 위험률 id 도 `r80` 처럼. 절은 조건에서 만들고 읽지 않는다 |
| (v2) 담보마다 세로 표, 현가율 값 행 없음 | 9칸 넓은 표는 쪽을 넘쳤다. v^t 는 이율에서 계산하는 값이라 문서에 싣지 않는다 |
| 자동 식과 같은 식은 조건에 싣지 않는다 | 조건이 바뀌면 식도 따라 바뀌어야 한다. 사람이 고친 식·새 식만 조건(M08)에 남아 자동 식을 대신한다 |
| 위험률 표에 **기호** 칸 | 담보가 가리키는 위험률 id 가 문서를 거쳐도 그대로 돌아온다 |
| 작성일은 조건에 적힌 것만 싣는다 | 오늘 날짜가 찍히면 되읽을 때 조건이 아닌 값이 섞인다(자유설계보험 인쇄는 `today` 를 넘겨 날짜를 찍는다) |
| 상품별 견본은 목록 한 줄 | `lib/standards.ts` 의 `STANDARDS` — 파일 이름 `표준_산출방법서_<이름>`. `.hwpx` 는 한글에서 `.docx` 를 저장한 것 |

흐름: [Word 내려받기] → Word·한글에서 고침 → [고친 Word·한글 올리기] = `parseMethodDoc` → `mergeSpec`(식·주석·절·회사/판/비고까지) → `patchYaml`(조건 파일 주석 유지).
쓰는 규칙은 [`../standards/README.md`](../standards/README.md).

## 5. 제안 — 조건 → 산출방법서 파일

| 형식 | 상태 | 비고 |
|---|---|---|
| `.tex` | ✅ | `\documentclass{article}` + kotex. `xelatex 파일.tex` 로 바로 조판 |
| `.md` | ✅ | 수식은 코드 블록(평문 표기) |
| `.html` | ✅ | KaTeX 로 그린 수식 포함 단독 파일 |
| 인쇄 · PDF | ✅ | 브라우저 인쇄(산출방법서만) |
| `.docx` | ✅ | `docx.ts` 가 직접 쓴다(의존성 없음). 표준 산출방법서 — 작성 안내 포함/없이. 한글에서 열어 HWPX 로 저장 |
| 회사 양식 | 제안 | 표지·머리말·절 번호 체계를 LaTeX 템플릿 파일로 받아 채우기 |

## 7. 제안 — AI 보조

flexible_insurance 의 `llm.ts`(규칙이 못 찾은 항목만 문단 발췌로 묻기)가 이 모듈에 그대로 들어 있다.
mdTeX Studio 처럼 **사용자가 앱에서 API 키를 입력**하는 방식으로 켜면 서버 없이 쓸 수 있다.
특히 **담보 표**가 규칙으로 잘 안 뽑히는 외부 PDF(지금은 담보 0개)에서 효과가 크다.

## 8. 알려진 한계

- 외부 PDF 의 **담보**는 규칙으로 뽑지 못한다(이 앱이 낸 문서의 담보 표만 되읽는다) — 직접 적거나 AI 보조.
- 표준 산출방법서의 **계약 단위 표**(주계약·특약)는 이름·담보만 보여 주는 표라 [열기]로 되살리지 않는다 — [조건에 반영]은 지금 계약 단위를 그대로 둔다.
- **납입기간**은 산출방법서에 없는 경우가 대부분이다(사업방법서 소관).
- 위험률 **값 표**는 조건 파일에 싣지 않는다 — 아래 위험률 표 창에서 열을 이어 붙이고, JSON 과 산출방법서 별첨에는 실린다.
- 위험률 표는 XLSX 첫 시트만 읽는다(옛 .xls 는 못 읽음 — .xlsx·.csv 로 저장). 수식 칸은 Excel 이 저장해 둔 값을 쓴다.
- 문장 수정은 조건이 아니라서 [조건에 반영] 되지 않는다 — LaTeX·Markdown 파일로 내려받아 보관한다.
- 일부 PDF 는 기호 글꼴이 깨진 글자로 추출된다(pdf.js 글자 레이어 한계).
